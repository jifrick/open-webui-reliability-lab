# P01 — Header Archive unarchives an already archived chat

## Candidate and current status

- **Issue:** [open-webui/open-webui#31473](https://github.com/open-webui/open-webui/issues/31473)
- **Live state checked:** Open; created 2026-09-27, updated 2026-09-27. Checked 2026-10-01.
- **Reported scope:** In the chat header action menu, choosing “Archive” for an already archived chat toggles it back to active while still showing an archive-success toast.
- **Affected users:** Anyone opening an archived chat from Archived Chats and using the header menu; the misleading label and confirmation make the state reversal easy to miss.

## Reproduction and verification

**Reported steps (from the issue):**
1. In an active chat, choose Archive from the header menu.
2. Open the chat from Settings → Archived Chats.
3. Open the header menu and choose its displayed Archive action.
4. Observe the chat return to the regular sidebar and disappear from Archived Chats. Reload to check persistence.

**Reported result:** The action says “Chat archived.” but the chat is unarchived and remains active after reload.

**Independent check:** Source inspection confirms that the menu label and toast are unconditional while the server operation toggles state. No full browser/API reproduction was run in this research. The issue’s report is therefore not represented here as an independently observed UI run.

## Source and source-backed cause

At imported `main` (`8bd8b4fac5e059578ac0c74b3c18d11139f88b7d`):

- [`src/lib/components/layout/Navbar/Menu.svelte`, header menu archive item](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/components/layout/Navbar/Menu.svelte#L475-L488) always renders “Archive” and invokes the supplied handler.
- [`src/lib/components/chat/Chat.svelte`, `archiveChatHandler`](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/components/chat/Chat.svelte#L4109-L4120) calls the archive API, refreshes lists, then always reports “Chat archived.”
- [`backend/open_webui/routers/chats.py`, `archive_chat_by_id`](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/backend/open_webui/routers/chats.py#L1909-L1935) calls the toggle operation and branches on the resulting archived state.

**Cause established from source:** The API intentionally toggles archive state, but the header menu and handler treat the operation as archive-only. Thus a second invocation unarchives the chat while the UI still says Archive/archived. This conclusion is source-backed; the issue’s claim that this occurs is also consistent with the path.

## Proposed solution

Expose the chat’s current archived state to the header menu, present Archive or Unarchive accordingly, and use the API result (or refreshed authoritative state) for the confirmation. Keep the existing toggle semantics only if all callers explicitly handle both outcomes; an explicit archive/unarchive API could be considered separately but is not required for this UI defect.

## Acceptance criteria

- An active chat’s header action reads Archive; choosing it removes the chat from active lists, places it in Archived Chats, and reports that it was archived.
- An archived chat’s header action reads Unarchive; choosing it restores the chat to the appropriate active location and reports that it was unarchived.
- State and action remain correct after reload; a failed request does not show a success toast or claim the opposite state.
- Other archive surfaces and their behavior remain unchanged.

## Regression-test plan

- Component or browser test for menu text in active and archived states.
- Mock archive API responses for both resulting states; assert the correct toast and refresh behavior.
- Browser/API workflow: archive, reopen from Archived Chats, unarchive from header, reload, and verify sidebar/Archived Chats placement.
- Include failed-request coverage and check the search-dialog archive behavior remains intact.

## Risks and dependencies

- Ensure the header receives fresh archive state when opened from Archived Chats and after state changes elsewhere.
- The endpoint returns a toggled result; do not derive the toast from the requested action alone.
- Keep translation keys/localization aligned for Unarchive and state-specific notifications.
