# P07 — Archiving a chat loses tag display names

- **Issue/status:** [#30454](https://github.com/open-webui/open-webui/issues/30454), open, labels `bug` and `confirmed issue`; created 2026-09-24, updated 2026-09-27 (checked 2026-10-01).
- **Affected users / impact:** Users who archive a chat that is the only active user of a human-readable tag. After restore, the tag’s normalized ID may be shown as its name; the issue says that renamed value then appears in suggestions and is permanent for every chat using that tag.
- **Concrete reproduction (issue steps):** Start a chat; add a tag displayed as `My Project` (the UI uses spaces to separate tags, so the reporter’s exact workaround is to paste the name and press Enter); use it on no other chat. Archive from the sidebar, open Settings → Archived Chats, unarchive that chat, and inspect its tag and suggestions. Expected: `My Project`; reported result: `my_project`. The reporter states default configuration and no log output.
- **Source-backed behavior:** At dev `015dbc8`, `backend/open_webui/routers/chats.py:1920-1940` toggles archive status. On archive it calls `Chats.delete_orphan_tags_for_user(tag_ids, ...)`; on unarchive it calls `Tags.ensure_tags_exist(tag_ids, ...)`. `backend/open_webui/models/chats.py:2380-2428` counts only non-archived chats before deleting orphan tag rows. `backend/open_webui/models/tags.py:122-135` derives IDs by lowercasing/replacing spaces, then uses each supplied string as the new tag’s display `name`. Tag suggestions are served from stored tag rows (`routers/chats.py:1035-1041`).
- **Direct reproduction / limits:** Ran the actual `ensure_tags_exist()` method with a fake empty DB and the unarchive ID `my_project`. Exact output: `created tags: [('my_project', 'my_project')]`. This verifies lossy reconstruction; it is not a complete persistent archive/unarchive round trip, nor a browser reproduction.
- **Source-backed root cause (distinct from report):** The archive operation removes the tag row when no active chat references it, but archived chat metadata retains only the normalized tag ID. Unarchive passes that ID to a helper that interprets input as a display name. Once the original tag row is deleted, its spelling/casing/spacing is unrecoverable from the ID.
- **Related PRs / duplicates:** [#30951](https://github.com/open-webui/open-webui/pull/30951) proposes retaining tag rows while archived chats reference them and hiding archive-only tags from suggestions; it closed unmerged, and no public closure rationale was surfaced in the returned PR details. [#30954](https://github.com/open-webui/open-webui/pull/30954) snapshots display names in chat metadata and restores from that snapshot; it also closed unmerged. Bot comments give specific process reasons: missing CLA text, target `main` rather than required `dev`, and missing eligibility confirmation. Neither is a merged fix. [#30453](https://github.com/open-webui/open-webui/pull/30453) merged 2026-09-24 (commit `31bc59f1b3cc22d961b40d5bc1391865e4e2ff0b`) for bulk Unarchive All/Delete All behavior related to #30452; it is not a fix for preserving names in single-chat archive/restore.
- **Main/dev and release history:** In imported `main` `8bd8b4f` and upstream `dev` `015dbc8`, the single-chat archive cleanup and ID-based unarchive recreation remain. Dev additionally has the #30453 bulk behavior: `routers/chats.py:1131-1143` collects IDs from archived chats before Unarchive All and recreates missing tag rows; Delete All similarly cleans unused tag rows. These changes restore by ID and do not preserve a deleted tag’s original display name. v0.11.4 was released 2026-09-21, before #30454; no later release or changelog entry for this issue was found.
- **Proposed solution:** Preserve the canonical display name along with tag IDs while archived, or retain tag rows for archived references but exclude archive-only tags from suggestions. Choose one persistence/visibility policy deliberately; do not treat a slug as a reversible display name. Ensure single and bulk flows use the same invariant.
- **Acceptance criteria:** `My Project` and other mixed-case/spaced names survive single and bulk archive/restore; tag ID and association remain stable; tag suggestions include/exclude archived-only tags according to the chosen policy; legacy archived chats without saved display-name data remain safe and predictable.
- **Regression plan:** Persistence-level round trips for single and bulk archive/restore; test a unique tag and one shared with an active chat; verify suggestions and search before/after; include lower-case IDs, spaces, mixed case, legacy archived metadata, and delete/restore interactions.
- **Risks / dependencies:** Retaining tag rows may affect suggestion/search semantics and cleanup; storing a name snapshot requires metadata compatibility and a migration-free fallback for older chats. Competing closed PRs reflect distinct policy choices; maintainer preference should be established before implementation.
