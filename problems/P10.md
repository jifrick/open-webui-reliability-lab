# P10 — Anthropic deferred tools and `tool_reference` conversion

- **Issue/status:** [#31407](https://github.com/open-webui/open-webui/issues/31407), open, label `enhancement`; created 2026-09-25, updated 2026-09-27 (checked 2026-10-01). A maintainer classified this as missing feature support, not a bug.
- **Affected users / impact:** Anthropic-compatible clients using client-side tool discovery against an OpenAI-compatible provider through Open WebUI’s conversion path. The issue reports deferred schemas are sent immediately and discovery `tool_reference` results disappear, reducing the value of client-side lazy loading and potentially increasing model prompt size. This is not applicable to native Anthropic passthrough connections that bypass conversion.
- **Concrete reproduction (issue scenario):** Submit an Anthropic Messages payload containing a regular `ToolSearch` definition and a second definition with `defer_loading: true`; inspect the converted OpenAI request. Then include an assistant `tool_use` for `ToolSearch` and a following user `tool_result` whose content is `[{\"type\":\"tool_reference\",\"tool_name\":\"lookup\"}]`; inspect the translated tool message. Issue also provides a direct converter script and says it reproduced against v0.11.4 and dev, executing the converter in isolation (not claiming full deployment).
- **Direct reproduction / exact output:** Executed the current converter from this worktree with synthetic payloads. Output: `tools forwarded: ['ToolSearch', 'lookup']`; `translated discovery tool content: ''`. This verifies both behaviors at function level. It does not verify a live upstream provider’s prompt/token counts or all Anthropic tool-search variants.
- **Source-backed behavior:** At dev `015dbc8`, `backend/open_webui/utils/anthropic.py:138-366` converts Anthropic messages. In `tool_result` list handling (starts near line 249), recognized types include text, image, document, and search result; there is no `tool_reference` case, leaving `converted_parts` empty and tool content `''`. Tools conversion around lines 435-453 maps every `tools` entry from `input_schema` to an OpenAI function and never checks `defer_loading`.
- **Source-backed root cause (distinct from report):** The adapter implements ordinary Anthropic tool definitions and several result content types but does not model deferred-tool activation or the `tool_reference` result type. It therefore includes deferred schemas in the OpenAI request and silently omits the unknown reference block. Whether the resulting token/cost increase is material depends on client/provider payload and was not measured here.
- **Related work / duplicate/equivalent-fix check:** No PR matching #31407, `defer_loading`, or `tool_reference` was found. Merged [#31343](https://github.com/open-webui/open-webui/pull/31343) (commit `bc7dbc4b1ddd6573263eab018a0ef22df4c13adf`, Sep 27) omits empty tools and orphan `tool_choice`; it does not implement deferred semantics. Closed [#23188](https://github.com/open-webui/open-webui/issues/23188) requests other `tool_result` types; current converter handles several of them, but not `tool_reference`. Closed [#25963](https://github.com/open-webui/open-webui/pull/25963) concerned parallel Anthropic streaming/client-managed tools and was closed with a maintainer saying it should be addressed in dev; it is not an equivalent deferred-tools fix. Open [#31651](https://github.com/open-webui/open-webui/pull/31651) proposes Open WebUI’s own dynamic/lazy tool loading for its tool catalog, and explicitly distinguishes this issue’s Anthropic-native deferred fields.
- **Main/dev and release history:** Imported `main` `8bd8b4f` and dev `015dbc8` both convert every tool definition and omit `tool_reference`; reviewed dev converter changes do not implement these semantics. v0.11.4 was released 2026-09-21, before #31407; no later release or changelog entry for the candidate was identified.
- **Proposed solution:** If supported, interpret `defer_loading` according to the supported Anthropic client contract: keep unactivated deferred schemas out of model-visible tools, activate definitions when referenced or otherwise selected by an explicit documented rule, and translate `tool_reference` into a meaningful compatible representation rather than silently empty content. Preserve passthrough behavior and ordinary tool conversion. Confirm protocol/version semantics before choosing how a reference maps to OpenAI-compatible tool context.
- **Acceptance criteria:** Ordinary tools remain unchanged; deferred tools are not sent before activation and are available when requested; reference results remain nonempty and identifiable; prior tool calls and forced choices remain valid; incoming payload is not mutated; native Anthropic passthrough remains untouched. Document unsupported server-side search variants.
- **Regression plan:** Converter unit fixtures for deferred and normal tools, `ToolSearch` plus references, multiple references/results, previously called and forced tools, empty tool arrays/choice, text/image/document/search results, and passthrough. Add route-level tests for converted requests/responses and provider contract tests where feasible; verify generated request contents rather than inferring token savings.
- **Risks / dependencies:** Anthropic client and provider protocol variation, preserving tool identity through OpenAI’s function schema, ordering of discovery/result messages, prompt size, and compatibility of a textual reference representation. Treat this as a feature proposal; the maintainer confirms current behavior is intentional absence of support.
