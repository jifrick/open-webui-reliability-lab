# P03 — Ctrl+Shift+Enter also submits when Ctrl+Enter-to-Send is enabled

## Candidate and current status

- **Issue:** [open-webui/open-webui#31468](https://github.com/open-webui/open-webui/issues/31468)
- **Live state checked:** Open; created 2026-09-27, updated 2026-09-29. Checked 2026-10-01.
- **Reported scope:** With Ctrl+Enter-to-Send enabled, Ctrl+Shift+Enter (Generate Message Pair) submits the prompt as well as creating the placeholder pair. The issue also reports the Mac Cmd+Shift+Enter equivalent.
- **Affected users:** Users relying on the pair-generation shortcut, especially when using Ctrl/Meta+Enter to send.

## Reproduction and verification

**Reported steps (from the issue):**
1. Set Enter Key Behavior to Enter to Send, enter a prompt, and press Ctrl+Shift+Enter. The report says this creates a placeholder pair without asking the model.
2. Set Enter Key Behavior to Ctrl+Enter to Send.
3. In a fresh chat, enter a prompt and press Ctrl+Shift+Enter.
4. Observe the real completion and the extra placeholder pair; reload to check persistence.

The reporter’s follow-up, [comment with Playwright/mock-endpoint observations](https://github.com/open-webui/open-webui/issues/31468#issuecomment-5883908784), reports:

| Preference | Completion POSTs | Model endpoint requests | Observed result |
|---|---:|---:|---|
| Enter to Send | 0 | 0 | User text plus placeholder response |
| Ctrl+Enter to Send | 1 | 1 | Mock response plus an extra `[PROMPT]` / `[RESPONSE]` pair |

The reporter says the extra pair disappears on reload; they did not trace persistence ordering.

**Independent predicate check:** Evaluated the current source’s send condition in a Node harness with `{ key: 'Enter', keyCode: 13, ctrlKey: true, metaKey: false, shiftKey: true }`. Output:

```json
{"event":{"key":"Enter","keyCode":13,"ctrlKey":true,"metaKey":false,"shiftKey":true},"ctrlEnterToSend":true,"enterToSend":false}
```

This verifies the predicate only. It does not exercise browser event propagation, DOM handling, or an actual completion request. The request-count evidence above is the reporter’s controlled Playwright test, not a reproduction run in this worktree.

## Source and source-backed cause

At imported `main` (`8bd8b4fac5e059578ac0c74b3c18d11139f88b7d`):

- [`src/lib/components/chat/MessageInput.svelte`, composer keydown handler](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/components/chat/MessageInput.svelte#L2110-L2170) computes `isCtrlPressed` from Ctrl or Meta. When Ctrl+Enter-to-Send is enabled, `enterPressed` requires Enter and that modifier but does not exclude Shift (around lines 2155–2168).
- [`src/routes/(app)/+layout.svelte`, `GENERATE_MESSAGE_PAIR` keybinding handler](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/routes/%28app%29/+layout.svelte#L321-L324) independently clicks the pair-generation button for the same shortcut. This handler does not check whether the composer has already handled or submitted the event.
- [`src/lib/shortcuts.ts`, default keybinding](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/shortcuts.ts#L85-L105) defines Generate Message Pair as `Cmd+Shift+Enter`.

**Cause established from source:** The Ctrl/Meta+Enter submit predicate is satisfied even when Shift is pressed, while the document-level pair shortcut also matches that chord. The two actions are not mutually exclusive. This confirms the collision mechanism; the reported duplicate visible/persisted result is supported by the reporter’s Playwright run, not independently established here.

## Proposed solution

Make the two chords exclusive. For example, require `!e.shiftKey` in the Ctrl/Meta+Enter submit condition, or explicitly guard the pair shortcut from submit. Preserve the existing Ctrl/Meta and Enter behavior for ordinary submission. Avoid relying only on `preventDefault()` unless propagation and component event behavior are also handled.

## Acceptance criteria

- Ctrl/Meta+Shift+Enter creates exactly one placeholder pair and sends no completion request under either Enter preference.
- Ctrl/Meta+Enter without Shift still submits when Ctrl+Enter-to-Send is enabled.
- Enter without Shift still submits when Enter-to-Send is enabled; Shift+Enter behavior remains unchanged.
- The shortcut works on supported Ctrl/Meta platforms and does not create an empty extra pair.

## Regression-test plan

- Unit-test the key predicate over Enter preference × Ctrl/Meta × Shift combinations, including `keyCode === 13` compatibility.
- Browser test with a mock completion endpoint; assert zero completion requests for the pair shortcut and one for ordinary send.
- Assert message history contains only the intended user text and one placeholder pair, and verify persistence after reload.
- Include both Windows/Linux Ctrl and macOS Meta mappings where the test harness supports them.

## Risks and dependencies

- `preventDefault()` prevents default browser behavior but does not itself stop event propagation; consider event ordering and Svelte component dispatch.
- Keyboard shortcut matching and composer submission are separate handlers. Tests should guard against reintroducing collisions in either.
- Do not break IME composition handling, mobile behavior, or keyCode fallback paths.
