# P05 — Deleting the active chat leaves a stale folder entry

## Candidate and current status

- **Issue:** [open-webui/open-webui#31321](https://github.com/open-webui/open-webui/issues/31321)
- **Live state checked:** Open; created 2026-09-24, updated 2026-09-30. Checked 2026-10-01.
- **Reported scope:** Deleting the open chat with the Delete Chat keyboard shortcut removes it from the backend, but its row remains in the sidebar folder until page reload.
- **Affected users:** Users deleting the currently open conversation from a folder, especially via Ctrl+Shift+Backspace. The stale row can open a chat that no longer exists.

## Reproduction and verification

**Reported steps (from the issue):**
1. Create and expand a folder.
2. Start a chat inside the folder and send a message.
3. With that chat open, press Ctrl+Shift+Backspace and confirm deletion.
4. Observe the row remain under the folder; click it to observe the stale target.
5. Reload and verify the row is gone.

**Reported result:** Backend deletion succeeds, but the folder listing stays stale until reload.

**Independent check:** Source tracing confirms that the active-chat deletion flow refreshes the main/pinned chat list but does not refresh or invalidate folder lists. No full UI/API deletion run was performed in this worktree, so the visible stale-row result remains reporter evidence.

## Source and source-backed cause

At imported `main` (`8bd8b4fac5e059578ac0c74b3c18d11139f88b7d`):

- [`src/lib/components/chat/Chat.svelte`, `confirmDeleteChat`](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/components/chat/Chat.svelte#L4141-L4155) deletes the active chat, navigates home, refreshes the main/pinned chat list and tags, and shows a success toast. It does not call `refreshFolderChatLists`.
- [`src/lib/stores/chatList.ts`, `refreshFolderChatLists`](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/stores/chatList.ts#L70-L85) exposes a separate folder-list refresh bridge.
- [`src/lib/components/layout/Sidebar/ChatItem.svelte`, `deleteChatHandler`](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/components/layout/Sidebar/ChatItem.svelte#L250-L271) dispatches a `change` event after successful deletion. Folder/sidebar components propagate this event; the active-chat handler does not use that path.
- [`src/lib/components/layout/Sidebar/RecursiveFolder.svelte`, `setFolderItems`](https://github.com/open-webui/open-webui/blob/8bd8b4fac5e059578ac0c74b3c18d11139f88b7d/src/lib/components/layout/Sidebar/RecursiveFolder.svelte#L532-L590) maintains and reloads folder chat rows separately.

**Cause established from source:** Folder rows are independently held/refreshed client state. The successful active-chat deletion branch updates the main list but omits the folder refresh/event that other sidebar deletion flows use. This establishes the invalidation gap. The exact user-visible stale row was not independently reproduced here.

## Proposed solution

After confirmed active-chat deletion, invalidate or refresh the relevant folder chat lists using the existing sidebar refresh mechanism (or dispatch the same change event consumed by the sidebar). Refresh only after successful deletion; preserve failure behavior and update main/pinned state as today. Consider the selected folder and expanded-folder registry without requiring a full page reload.

## Acceptance criteria

- After successful deletion of the active chat from an expanded folder, its row disappears immediately from that folder and all other relevant sidebar views.
- Clicking the stale row is no longer possible; reload produces the same state.
- Failed deletion leaves folder and main-list entries intact and does not show success.
- Deletion outside a folder, pinned state, nested folders, and normal sidebar-row deletion continue to behave correctly.
- Refresh does not remove unrelated chats, disturb folder expansion, or unnecessarily reload the whole page.

## Regression-test plan

- Browser test: create/expand folder, open a chat in it, invoke the Delete Chat shortcut, confirm, then assert row absence without reload.
- Assert API deletion success and failure paths; on failure, retain the row and display an error.
- Cover nested and collapsed/expanded folders, the main chat list and pinned section, plus deletion initiated from the sidebar row.
- Reload after success and verify server and client state agree.

## Risks and dependencies

- Folder state is held in a component registry separate from the main/pinned chat stores; ensure the refresh bridge reaches mounted expanded folders.
- Do not refresh before deletion succeeds or hide an entry after a failed request.
- Avoid changing unrelated bulk-action/unarchive invalidation semantics already addressed by #30180.
