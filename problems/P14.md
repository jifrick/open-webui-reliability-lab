# P14 — Multi-model response actions can be clipped without a visible cue

- **Issue:** [open-webui/open-webui#31637](https://github.com/open-webui/open-webui/issues/31637)
- **Current status:** Open when checked 2026-10-01; updated 2026-09-30.
- **Affected users:** Users comparing three or more model responses, particularly users relying on custom Actions, Fork chat, or timestamp controls.
- **Reported reproduction:** The reporter reproduced on v0.11.4 and `dev` commit `3819dc279`. Start a clean instance with provider APIs disabled; add a pipe exposing three echo models and three global no-op Action functions; open a chat with those three models, send a message, and inspect each response action row at a 1280-pixel viewport. The issue reports only the first custom Action visible, with remaining Actions, Fork chat, and timestamp clipped; wheel-scrolling over the row reveals them. The report says two models fit the Actions but clip the timestamp.
- **Observed / expected:** Reported row width is about 237 px against about 405 px of controls at three columns. Expected is every response action visible and discoverable/clickable regardless of model count.
- **Independent reproduction:** Not run in a local browser. The issue includes environment, pipe/action code, viewport, measured widths, and screenshots. Current source corroborates the non-wrapping horizontal scroller and hidden scrollbar. The baseline has no in-repository browser test suite and Cypress's browser binary was skipped, so this dossier does not claim an independent visual reproduction.
- **Source locations:** `src/lib/components/chat/Messages/ResponseMessage.svelte` renders the action row with `overflow-x-auto whitespace-nowrap` and non-shrinking children; its `.buttons` CSS hides scrollbars for WebKit, IE/Edge, and Firefox. `src/lib/components/chat/Messages/MultiResponseMessages.svelte` lays out response columns in a horizontally scrolling row.
- **Root cause:** The action row is constrained by the multi-model response column, forces its children onto one line, and hides the scrollbar. Horizontal overflow remains technically scrollable but there is no visible indication that further actions exist; this matches the reporter's measurements and described behavior.
- **Linked PRs / duplicate check:** No matching PR was returned for #31637 when checked. Related #10604 (closed 2025) described controls cut off in multi-model columns after regenerating; its discussion confirms vertical-wheel scrolling as a workaround. The current report is narrower and current-version-specific: it demonstrates clipping of custom Actions, Fork chat, and timestamp controls in a three-model response row with hidden-scrollbar behavior. #26846 concerns a separate truncated rating scale and is closed. These overlaps should be rechecked before implementation.
- **History / release check:** Upstream `main` is `8bd8b4fac5e059578ac0c74b3c18d11139f88b7d`; `dev` is `015dbc8619568ac077ec1d782661836a63691ba1` (checked 2026-10-01). The action-row layout in `ResponseMessage.svelte` is unchanged between these revisions; unrelated edits do not add wrapping or a visible affordance. Latest official release is v0.11.4; the issue reports both v0.11.4 and dev reproduction.
- **Proposed solution:** At narrow multi-model widths, wrap actions into multiple rows or provide a clear, keyboard-accessible overflow affordance and preserve access to all actions. Avoid silently hiding a horizontal scrollbar while retaining mandatory no-wrap content.
- **Acceptance criteria:** With one, two, three, or more model columns, all response actions can be discovered and activated; keyboard and touch users can reach overflow controls; action targets remain associated with the correct model response; layout does not obscure response content.
- **Regression test:** Browser test with three response columns and multiple custom actions, checking that every action is visible or exposed through an accessible overflow control and remains clickable. Include keyboard focus traversal, viewport sizes, and single-/two-model layouts.
- **Risks:** Wrapping may increase vertical height or alter control alignment; horizontal scrolling may remain desirable on narrow screens; action visibility conditions and accessibility semantics must remain intact.
- **Dependencies:** Browser regression harness and a deterministic test fixture for multiple model responses/custom Actions.
