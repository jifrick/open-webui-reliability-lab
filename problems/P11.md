# P11 — Renamed knowledge file keeps its old citation name

- **Issue:** [open-webui/open-webui#30318](https://github.com/open-webui/open-webui/issues/30318)
- **Current status:** Open when checked 2026-10-01; updated 2026-09-21.
- **Affected users:** Knowledge-base users who rename a file after indexing and then retrieve it in later chats.
- **Reported reproduction:** Create a knowledge base, upload a uniquely named file with quotable text, attach the knowledge base in a chat and inspect sources, rename the file, then start a new chat, attach the same knowledge base, and ask the same question. The knowledge-base list and picker show the new name while the source chip and citation panel retain the original name until reindex.
- **Observed / expected:** The old indexed name is displayed after rename; the requested behavior is current filename in subsequent citations.
- **Independent reproduction:** Reproduced through the current production `get_sources_from_items` function using a mocked file store and vector query result. The file record reported `new-name.pdf`; the vector metadata contained `old-name.pdf`; returned citation metadata still had `name=old-name.pdf` and `source=old-name.pdf`. The harness exercised current source assembly, but did not use a live database/vector backend or browser.
- **Source locations:** `backend/open_webui/routers/retrieval.py` writes `name` and `source` from `file.filename` into indexed document metadata. `backend/open_webui/models/files.py::Files.update_file_name_by_id` updates the database row's `filename` and `meta`, not the vector collection. `backend/open_webui/retrieval/utils.py::get_sources_from_items` queries the vector collection and returns its `metadatas` without resolving the filename from `file_id`; the UI renders `metadata.name` in `src/lib/components/chat/Messages/Citations.svelte`.
- **Root cause:** The source confirms a denormalized filename snapshot is stored with vector chunks; rename updates the file record but not existing chunk metadata, and citation source assembly passes that stale metadata through.
- **Linked PRs / duplicate check:** PRs [#30344](https://github.com/open-webui/open-webui/pull/30344) and [#31562](https://github.com/open-webui/open-webui/pull/31562) both describe read-time filename resolution. Both were closed without merge; the issue remains open. A current-main/current-dev source comparison found no read-time filename lookup in `get_sources_from_items`. No official matching PR was found open or merged when checked. Recheck before any implementation.
- **History / release check:** Upstream `main` is `8bd8b4fac5e059578ac0c74b3c18d11139f88b7d`; `dev` is `015dbc8619568ac077ec1d782661836a63691ba1` (checked 2026-10-01). Relevant source behavior is present in both. The latest official release is v0.11.4 (2026-09-21); issue report says it reproduced on dev commit `c07fa08b9`. The closed PR patches are not included in current dev.
- **Proposed solution:** At source assembly time, resolve existing file IDs to the current authorized file name, while preserving stored labels for deleted files and sources without a file ID. Apply consistently to all citation-producing paths, including knowledge and direct file retrieval.
- **Acceptance criteria:** After renaming an indexed file, new retrievals show the current name in the source chip and citation panel without reindex; deleted files and external/URL sources remain readable; access-control checks are preserved; vector-backed citations do not expose names from inaccessible files.
- **Regression test:** Unit-test source metadata assembly with stale name/source plus a file ID, a renamed authorized file, a deleted file, and external/URL sources. Add API/UI integration coverage asserting the current name is rendered after rename and reload.
- **Risks:** Additional database lookups per citation, deleted-file fallback semantics, backend-specific metadata, and avoiding name disclosure across file-access boundaries.
- **Dependencies:** Current `file_id` metadata, `Files.get_file_by_id`/authorization helpers, and consistent behavior across vector backends.
