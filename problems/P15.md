# P15 — Operators cannot exclude selected routes from OTEL metrics

- **Issue:** [open-webui/open-webui#31609](https://github.com/open-webui/open-webui/issues/31609)
- **Current status:** Open when checked 2026-10-01; updated 2026-09-29. This is an observability configuration request.
- **Affected users:** Operators exporting OpenTelemetry HTTP metrics to a time-series database, including Kubernetes users whose health probes add unnecessary request counts.
- **Reported reproduction:** Enable OTEL metrics and call the configured `/health`, `/health/db`, and other high-volume routes. The reporter says probe requests appear in exported metrics and provides a custom-image workaround. A follow-up requests wildcard support for static asset paths.
- **Observed / expected:** Current metrics include health-probe traffic; desired behavior is configurable route exclusions to reduce noise/cardinality while retaining metrics for other routes.
- **Independent reproduction:** Ran the actual `setup_metrics` middleware with stubbed metric instruments and a fake application/request, invoking `/health` and `/health/db`. Output was `counter_routes=['/health', '/health/db']; histogram_records=2`, confirming both routes are recorded unconditionally. The local environment lacks the OTLP HTTP exporter module, so that import and provider creation were stubbed; no live collector or exported OTLP payload was tested.
- **Source locations:** `backend/open_webui/utils/telemetry/metrics.py::setup_metrics` registers `_metrics_middleware`; its `finally` block resolves `http.route` and unconditionally calls `request_counter.add` and `duration_histogram.record`. `backend/open_webui/main.py` defines `/health` and `/health/db`. A separate upstream middleware comment says health paths are skipped by `AppHTTPMiddleware`, but that does not bypass the independently registered OTEL metrics middleware.
- **Root cause:** The metrics middleware has no route exclusion configuration or conditional branch; all requests reaching it are emitted to the request counter and duration histogram.
- **Linked PRs / duplicate check:** No matching Open WebUI PR was returned for #31609 when checked. The issue links external [OSC/open-webui commit `894561392ed966facc9df538a2d3e0f461774a0b`](https://github.com/OSC/open-webui/commit/894561392ed966facc9df538a2d3e0f461774a0b) (2026-09-29), which adds `OTEL_METRICS_SKIP_ROUTES` and guards both instruments. This is a separate fork, not an upstream fix; current official `main` and `dev` do not include it. Related #16183 is closed and concerns OTLP HTTP export, not route exclusion.
- **History / release check:** Upstream `main` is `8bd8b4fac5e059578ac0c74b3c18d11139f88b7d`; `dev` is `015dbc8619568ac077ec1d782661836a63691ba1` (checked 2026-10-01). `metrics.py` is behaviorally unchanged on dev and still records every request. Latest official release is v0.11.4 (2026-09-21); the report is newer and no later official release contains the request.
- **Proposed solution:** Add documented configuration for exact route paths and, if maintainers accept it, well-defined wildcard matching. Apply exclusions to both counter and histogram and keep tracing/logging semantics separate. Validate invalid patterns explicitly.
- **Acceptance criteria:** Configured route templates are omitted from both HTTP metrics; non-excluded requests remain instrumented; matching works deterministically for health routes and configured wildcard cases; defaults preserve current behavior or use a documented safe default.
- **Regression test:** Unit-test middleware with recording counter/histogram doubles for excluded and included paths, route templates, wildcard/path matching, invalid configuration, exceptions, and status-code retention. Integration-test that `/health` and `/health/db` produce no measurements when excluded.
- **Risks:** Overbroad patterns can create observability blind spots; raw paths can have high cardinality; route template matching and defaults must be documented.
- **Dependencies:** Route-pattern semantics, environment/configuration policy, and installed OpenTelemetry test dependencies.
