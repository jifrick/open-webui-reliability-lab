## Method

Candidates must be live, specific, useful to affected users, and technically understandable. For each candidate, the follow-up investigation must capture the issue URL, state/date, version/environment, reproduction, expected/observed behavior, supporting evidence, linked PRs/commits/releases, duplicate check, exact current source components, independently established root cause, solution, regression plan, risks, dependencies, and definition of done.

Reported cause is labelled as reported until confirmed against source. An issue being open does not prove that the behavior remains or that no PR exists. Re-run the checks before coding.
